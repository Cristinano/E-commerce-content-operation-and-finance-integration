企业级 Agent 的复杂性不只在模型，而在能力治理、记忆、数据、工作流和安全如何协同。下面用图解把 TaiChu AI 的平台能力落到业财一体化场景里。

01 · 总架构

AI 不是外挂，而是业财数据之上的经营智能层

CRM、PM、HR、FM 先把客户、合同、项目、产出、薪酬、成本、对账、应收和利润沉淀成统一经营数据。TaiChu AI 再把这些数据转成可追问、可解释、可行动的经营答案。

  • 业务系统负责沉淀真实数据。
  • Agent 平台负责理解问题、调用能力、生成答案。
  • 经营驾驶舱、预警、简报和问数共用同一套数据底账。

02 · Skill 治理

把零散能力变成可审核、可复用、可更新的平台资产

Skill 是 Agent 的标准工具箱。对客户来说，它意味着 AI 不是临时发挥，而是按企业认可的能力去查询数据、生成报表、发起提醒和执行流程。

  • 生命周期控制：草稿、审核、发布、下线都有规则。
  • 三级缓存保障：常用能力可快速加载，网络波动不影响核心体验。
  • 双写一致性：配置中心做权威源，本地库做快速读取。

03 · 记忆引擎

让 Agent 记住业务口径，而不是每次重新解释

企业问数最怕口径不一致。记忆引擎把客户规则、财务口径、项目 SOP、历史复盘和用户偏好沉淀下来，下一次问数时自动带入上下文。

  • L0 摘要用于快速匹配，L1 概览用于判断相关性，L2 详情用于深度解释。
  • 去重机制会判断 SKIP、CREATE、MERGE，避免把相似但相反的规则混在一起。
  • 会话压缩让连续追问成本更低，也不丢重点。

04 · Data Agent

管理层问一句话，系统要走完一条可信的数据链路

Data Agent 不是把问题直接交给大模型回答，而是把问题拆成意图识别、口径匹配、权限校验、查询分析、图表报告和追问下钻。

  • 先确认“收入、成本、利润、回款、人效”的业务口径。
  • 再查询 CRM、PM、HR、FM 中的真实数据。
  • 最后输出答案、图表、异常解释和建议动作。

05 · 毛利归因

复杂经营问题要拆成收入、成本、交付三条证据链

项目毛利偏低不是一个数字问题，而是经营归因问题。AI 要同时看合同单价、产出验收、薪酬分摊、外包费用、返工记录和对账金额。

  • 收入链判断是否单价低、产出未确认或对账滞后。
  • 成本链判断内部薪酬、外包和费用是否异常。
  • 交付链判断逾期、返工和审核记录是否拉低效率。

06 · 工作流

让 AI 从“回答问题”升级为“按流程持续办事”

工作流引擎把 LLM、数据库、HTTP、NL2SQL、条件判断和结束节点连接起来。复杂场景里，AI 不只是输出文字，还能触发提醒、生成简报、转人工确认。

  • 变量插值让上一步结果传给下一步。
  • 条件分支让高风险、低置信度和正常情况走不同路径。
  • 人工确认保留关键决策边界。

07 · 安全与生产保障

企业敢把 AI 接进核心数据，前提是可控、可查、可降级

能查真实经营数据的 AI，必须有权限、审计、脱敏、沙箱、限流、隔离和降级。否则越聪明，风险越高。

  • 权限控制决定谁能查哪些客户、项目和财务字段。
  • 审计日志记录每次 SQL、工具调用和模型调用。
  • 限流降级保证高峰期不拖垮核心系统。

08 · 落地路径

先让数据真实，再让 AI 可问、可解释、可预警

AI 不适合第一天就大而全上线。更稳妥的路径，是跟随业财数据成熟度逐步落地：先建立底账，再跑通闭环，再做驾驶舱，最后上线问数和自动化。

  • 先选一个年框客户跑通合同、项目、产出、对账、应收、回款和利润。
  • 再围绕月度复盘、项目毛利、预算消耗、回款风险、人效分析配置高频问数。
  • 最后扩展知识库、经营简报和自动化预警。

Final takeaway

企业级 Agent 的价值，是把 AI 放进可治理的经营闭环。

对业财一体化系统来说，Agent 不是一个单独聊天入口，而是连接客户合同、项目交付、产出薪酬、成本利润、对账回款和经营问数的智能执行层。

先有可信数据CRM、PM、HR、FM 把经营过程沉淀为统一底账。
再有智能问数Data Agent 把自然语言问题变成可审计的数据分析流程。
最后形成数字员工Skill、记忆、工作流和安全护栏把 AI 变成可执行、可追责的业务助手。
